# Распознавание вещей: что есть в 2026 и что выбираем

Задача: по фото вещи дать короткую подпись по-русски («Кружка», «Зимняя куртка», «Мусорное ведро»), быстро, без лишней памяти на телефоне, с возможностью уточнить на сервере.

## Что сейчас (сборка 12–14)

`VNClassifyImageRequest` из Vision — встроенная в iOS модель, ~1 300 классов, 0 МБ в приложении. Минусы, которые видно в тестах: классы общие («tool» вместо «мусорное ведро»), бытовые вещи получают низкую уверенность, словарь на русский — ручной. Это предел подхода, а не настроек.

## Варианты на устройстве

| Подход | Размер в приложении | Скорость | Качество на бытовых вещах | Русский |
|---|---|---|---|---|
| Vision `VNClassifyImageRequest` (сейчас) | 0 МБ | ~50 мс | слабое, закрытый список классов | через словарь |
| **MobileCLIP / MobileCLIP2** (Apple, open source) — zero-shot: сравниваем фото с *нашим* списком названий | S0 ≈ 50 МБ, S2 ≈ 70 МБ, B ≈ 170 МБ | 3–15 мс на Neural Engine | хорошее: список классов задаём сами (1–2 тыс. бытовых вещей), можно расширять без переобучения | да — названия сразу по-русски (эмбеддинги текста считаем заранее) |
| Core ML классификатор (MobileNetV3 / EfficientNet, ImageNet) | 10–20 МБ | ~10 мс | как Vision, те же 1 000 классов | через словарь |
| FastVLM 0.5B (Apple, 2025) — полноценная «описывающая» модель на телефоне | ≈ 1 ГБ | 1–3 с, греет телефон | отличное, свободный текст | да |
| Apple Foundation Models (iOS 26) | 0 МБ | — | **только текст**, фото не принимает | — |

Вывод по устройству: **MobileCLIP2-S2 (≈70 МБ) с собственным списком бытовых вещей** — лучшее соотношение. Память: модель грузится по требованию, ~100–150 МБ RAM во время распознавания, выгружается после. Это в 2–3 раза лучше Vision на наших сценах и работает офлайн.

## Варианты на сервере (уточнение)

| Подход | Качество | Цена за фото | Задержка | Хлопоты |
|---|---|---|---|---|
| Claude / GPT / Gemini через Edge Function | лучшее, свободный текст, контекст («что это, одним-двумя словами по-русски») | ≈ $0.001–0.003 (превью 320 px) | 1–2 с | минимальные: ключ + 40 строк кода |
| Своя модель Qwen3-VL 8B на GPU (Hetzner/RunPod) | очень хорошее | GPU от ~$0.3–0.5/час → выгодно только от ~100 тыс. фото в месяц | 0.5–1 с | хостинг, обновления, мониторинг |
| Qwen3-VL 2B / Moondream на CPU-сервере | среднее | дёшево | 3–6 с | то же |

Вывод по серверу: на старте **API-модель** (Claude) — не нужно держать GPU, качество максимальное; переход на свою модель имеет смысл при больших объёмах, код на телефоне не меняется.

## Предлагаемая схема (гибрид)

1. **На телефоне, мгновенно:** MobileCLIP2-S2 даёт подпись и уверенность. Если уверенность высокая — подпись ставится, ничего не отправляем.
2. **Если уверенность низкая** (или вещь из «редких») — на плитке значок «уточняем…», превью 320 px уходит в Edge Function `caption`, модель отвечает 1–3 словами по-русски, подпись обновляется. Офлайн — остаётся офлайн-подпись, уточнение в очередь.
3. Пользователь всегда может исправить; его правки — источник для расширения списка классов.

Порядок внедрения:
- Шаг 1 (быстро, 1 день): серверное уточнение через Claude — поднимет качество сразу, Vision остаётся офлайн-вариантом.
- Шаг 2 (2–3 дня): MobileCLIP2 в приложении, список ~1 500 бытовых вещей по-русски, порог уверенности по реальным фото.
