- **Темы для доступности** (идея 31.10.2026). Лучшая практика Apple — не плодить свои темы, а уважать системные настройки доступности, которые пользователь уже включил: «Увеличить контраст» (`colorSchemeContrast`), «Уменьшить прозрачность» (убрать матовое стекло), «Жирный текст» и Dynamic Type (размер шрифта), «Различать без цвета» (статусы не только цветом — у нас «запаковано» = оранжевый + замок, это уже ок), «Уменьшить движение» (без прыжков коробки). Для дальтоников отдельные палитры мало помогают — важнее иконки и подписи рядом с цветом. Что сделать: 1) высококонтрастный вариант палитры, включается сам при «Увеличить контраст»; 2) все тексты на Dynamic Type; 3) проверка контрастов WCAG AA в обеих темах. Возможная «своя» тема сверх этого — «Крупный шрифт и крупные плитки» для слабовидящих.
- **Токены в тарифах** (идея 31.10.2026, пока не делаем). Действия стоят токены (например, распознавание вещи); токены можно купить или заработать: отправил контактам информацию о Box Nº — условно 10 000, отзыв в Google — 1 000, пост в Instagram/X — 1 000 и т. д. В подписках Бесплатно / Про / Макс — включённое количество токенов в месяц. Связано с переосмыслением тарифов; учесть правила App Store про вознаграждение за отзывы (Apple запрещает поощрять отзывы в App Store; отзывы в Google/соцсети — отдельно проверить).
- **Биржа перевозчиков** (идея 01.11.2026). Перевозчики регистрируются в Box Nº (свой кабинет, подписка), пользователи получают от них цены на свой переезд. Мы не берём процент: вся сумма — перевозчику, наш доход — подписка перевозчиков.
  - *Пользователь:* снимает вещи, создаёт места; у места — размеры Д×Ш×В (можно выбрать стандартную коробку из списка) → приложение само считает **объёмный вес** (Д×Ш×В / делитель; делитель у каждого перевозчика свой, обычно 4000–6000) и хранит его; если есть весы — вводит фактический вес для точного расчёта. Без веса перевозчик указывает «цена уточнится по факту взвешивания».
  - *Что видит перевозчик:* только выбранные места — номер, тип, габариты, объёмный/фактический вес, пометки «Хрупкое» / «Открыть первым» (§13). Ни фото, ни названий вещей, ни стоимости, ни имени. ⚠ Для расчёта цены нужны ещё откуда/куда (город или индекс) и желаемые даты — согласовать, что это тоже видно.
  - *Пользователь решает, что отдать:* весь переезд одним переключателем или отдельные места (остальное — сам, почтой и т. п.). **Сейф (§10а) перевозчику и третьим службам не передаётся никогда** — об этом прямо пишем при включении доступа (для переезда целиком и для места).
  - *Перевозчик:* отвечает предложением (цена, сроки, условия: «по факту взвешивания»), пользователь выбирает. Дальше общение и оплата — напрямую между ними.
  - *Связь с описью §16:* опись для выбранного перевозчика + круг «заполнил вес/размер → вернул → скан → история весов» по этапам.
- **Арбитраж и страхование** (идея 01.11.2026). У нас есть фотоотчёт, что лежало в каждой коробке, — основа для споров и страховки груза (возможно, с партнёром-страховой). Главный риск — мошенничество: сфотографировал, но в коробку не положил. Возможные защиты (подумать):
  - для страхуемых мест принимать только снимки из камеры приложения (не из галереи), с серверным временем и хешем файла;
  - вещь снимается **в открытой коробке** (номер/коробка в кадре) — проверяем, что в кадре та же коробка (фото номера §11б);
  - фото запакованной коробки с целым скотчем (+ номерная пломба/скотч с номером) в момент запаковки и при передаче перевозчику; перевозчик со своей стороны фотографирует коробку при приёме и выдаче (общий журнал);
  - сверка веса: заявленный вес вещей/места vs вес при приёме у перевозчика — заметное расхождение = флаг;
  - лимит страховой суммы на место, страхование только мест с полным фотоотчётом и весом.
